# 通用写作参考

根据任务读取相关章节。日常写作和局部编辑的通用流程见 [Skill 入口](../SKILL.md)。

## 事实、来源与叙述身份

- 区分可核对的事实、可编辑原文和未确认信息。涉及作者的行为、经历、意见或感受时，第一人称须有任务证据支持。集体称呼也须有依据。
- 保留原文的名称、日期、数字、代码、引文和来源链接。引用报告中的比例或倍数时保留原值和测量口径。自行换算与来源不一致时指出差异，按任务要求说明计算过程。
- 面向首次接触主题的读者，用一句话交代专有名称指什么、与当前内容有何关系。材料有官方文档、仓库或原始来源时，在适当位置引用。
- 公开写作需要点名第三方的负面结果时，核对来源、影响范围与表述。用户已明确要求点名且材料支持时可以直接写。点名的授权影响交付时，先完成其余部分，再核实这一项。

## 删除与保留

- “删掉全文里的旧套餐”覆盖标题、正文、表格、示例、链接、目录、脚注和注释。同步清理指代、空标题与失效链接。检查同义称呼以及“旧套餐已停止提供”一类仍提及目标的表述。
- “删掉第二段里的旧套餐”只授权修改第二段及必要的结构衔接。其他段的同名内容、原始引文或代码示例按指定范围保留。
- “不要修改旧套餐的说明”表示保护内容。明确要求写禁止规则、废弃公告或历史记录时，相关内容属于交付物。
- 用户只要求润色时，保持原有立场、结论、信息顺序和详略。用户要求去掉标题时，也撤掉承担相同作用的独立加粗行或居中短句。

## 措辞与逻辑

- 写明主体、动作和对象。模糊的“搞定”“处理一下”可以换成具体动作，保留语境清楚的常用动词和专业术语。检查修饰关系、指代和动作主体是否与宾语冲突。
- 保留事实之间有依据的原因、影响和应对。把重要判断与支持它的事实写在一起。相邻段落提供新信息，收尾在内容完整处结束。
- 检查套话是否承载事实、限定或逻辑关系。用具名来源替换模糊归因。用机制、结果或有口径的数字说明影响。删除没有实质内容的铺垫、拔高、恭维和指令回声。
- 同一对象沿用同一名称。“从 A 到 B”表达实际顺序、范围或变化。分组和标题随内容组织，重点用加粗标出。
- 结合语境保留必要的虚词、长短句变化和自然口语。使用主动语态说明谁做了什么。执行者未知或无关时可用被动语态。
- 英文用常见词和自然连接。分词短语应交代实际动作、机制或有出处的结果。检查 `significantly improves` 是否有测量依据，`serves as` 是否比 `is` 多表达了含义。

## 体裁与格式

| 场景 | 优先检查 |
| --- | --- |
| 博客、演讲和传记 | 用事实支持第一人称。按实际过程或问题组织段落。 |
| 产品说明、落地页和幻灯片 | 每段可见文案都向目标读者提供信息或帮助操作。保留实际需要的界面标签。 |
| 短社交内容和访谈 | 采用自然口语节奏，保留引文原话和作者已有立场。 |
| 文档、API 说明和正式通知 | 说明动作、适用条件与必要解释。保留术语、代码、字段和命令。 |

- 局部编辑延续原文的语言、标点习惯和 Markdown 层级。独立 H1 与正文避免重复。标题覆盖内容即可。
- 按语言和发布渠道处理标点。中文与相邻拉丁字母或数字之间通常用半角空格，中文句末用全角标点。英文标题默认使用 sentence case。专有名称、受保护引文和代码沿用原样。
- 用段落表达连续推理。列表项目保持同一逻辑层级。冒号可用于定义或列举，避免把自然句子反复压成标签。装饰性加粗、emoji 和破折号需要有内容上的作用。
- 默认交付任务所需的内容和格式。过程说明、生成要求、修改记录、模型名和内部路径只有在读者确实需要时才入稿。
