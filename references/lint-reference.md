# 通用检测器参考

`scripts/tone_lint.py` 检查 UTF-8 纯文本和 Markdown 中的已知表达模式。检测结果包含原始行号、规则编号和修改建议。脚本只报告诊断，不修改输入文件，也不需要风格工作区。

## 调用形式

检测文件、标准输入和规则目录使用同一个命令入口。

```bash
python3 scripts/tone_lint.py draft.md
python3 scripts/tone_lint.py --format json draft.md other.md
printf 'Read the guide.\n' | python3 scripts/tone_lint.py -
python3 scripts/tone_lint.py --list-rules --format json
python3 scripts/tone_lint.py --self-test
```

`--format` 接受 `text` 和 `json`，默认值为 `text`。`--list-rules` 从检测器实际使用的目录输出规则，不读取文件。`--self-test` 检查内置示例。没有文件或独立检查选项时，参数解析报错。

## 严重级别和退出码

| 结果 | 含义 | 退出码 |
| --- | --- | --- |
| `PASS` | 没有匹配的已知模式 | `0` |
| `WARN` | 需要结合语境判断的线索 | `0` |
| `FAIL` | 匹配现有阻断规则 | `1` |
| 输入错误 | 参数无效、文件不可读或内容无法按 UTF-8 解码 | `2` |

同一次调用包含 `FAIL` 和 `WARN` 时，退出码为 `1`。输入错误写入标准错误，不输出不完整的 JSON 报告。`PASS` 只表示没有匹配的已知模式，不代表事实和语义已经通过复核。

`vf-001` 至 `vf-032` 保留原有中文规则及严重级别。`unslop-<编号>` 是新增通用提示，`source_rule` 记录对应的 `unslop:<编号>`。这些提示均为 `WARN`。规则由项目内部持有，运行时不读取其他已安装的 Skill。

## 诊断格式

默认文本格式保留 `FAIL  文件:行号:` 和 `WARN  文件:行号:` 前缀。每条诊断的下一行是修改建议。同一文件的 `FAIL` 排在 `WARN` 前，同一级别按原始行号和规则目录顺序排列。

JSON 报告包含 `files` 数组和 `failed` 布尔值。`files` 中每项包含输入时的 `path` 和 `diagnostics` 数组。标准输入的路径是 `-`。有 `FAIL` 时，`failed` 为 `true`。

每条诊断包含以下字段。

| 字段 | 含义 |
| --- | --- |
| `rule_id` | 稳定的本地规则编号 |
| `severity` | `FAIL` 或 `WARN` |
| `line` | 输入源码中的行号，从 `1` 开始 |
| `excerpt` | 排除代码和非正文内容后的整行文本 |
| `message` | 供人工复核的修改建议 |
| `source_rule` | 对应的 unslop 编号，本地旧规则为 `null` |

一条规则在同一行最多产生一条诊断。`lint(text)` 返回不可变诊断元组，文件读取和输出由 `lint_cli.py` 处理。文本和 JSON 格式都使用这次检测的结果。

规则目录的 JSON 包含 `rules` 数组，每项只有 `rule_id`、`severity`、`message` 和 `source_rule`。实际目录可由 `--list-rules --format json` 重新生成。

## 正文范围

检测器保留链接标签和 HTML 元素两侧的正文，并排除以下源码内容。

| 内容 | 处理方式 |
| --- | --- |
| 文件开头的 YAML frontmatter | 排除到匹配的结束标记 |
| 反引号或波浪线围栏 | 按开头字符和最短长度寻找结束标记，所属引用容器结束时也终止 |
| 缩进代码 | 区分代码块、段落续行和列表正文 |
| 行内代码 | 在当前文本块内使用等长反引号配对，保留合法的跨行代码 |
| 链接地址、裸 URL 和引用定义 | 排除地址与有效定义，保留可见链接标签和未定义的引用标识 |
| HTML 注释 | 排除完整注释内容 |
| `script`、`style`、`pre` 和 `code` 元素 | 排除元素内容，保留相邻正文 |
| 其他 HTML 标签 | 排除标签和属性，保留元素正文 |

转义符决定标签或反引号是否属于语法。排除内容时保留换行，因此报告仍使用原始行号。检测器识别常见源码结构，不执行 JavaScript、CSS 或完整 Markdown 渲染。复杂排版的最终可见结果仍需要人工检查。

引用定义在全文范围内解析，允许先使用、后定义。标识匹配会折叠大小写、去除首尾空白，并合并内部连续空白。代码或隐藏 HTML 中的伪定义不参与解析，缺少有效目标的定义也不会隐藏正文。块边界和引用身份的依据见 CommonMark 的 [块与行内结构](https://spec.commonmark.org/0.31.2/#blocks-and-inlines) 和 [引用链接](https://spec.commonmark.org/0.31.2/#links)。

## unslop 覆盖范围

下表沿用 unslop 的稳定编号。自动提示只能识别已列出的词和结构，语义判断仍由 [通用写作规则](universal-writing-rules.md) 负责。

| 编号 | 检查对象 | 自动提示与人工边界 |
| --- | --- | --- |
| `3` | 空泛的分词短语 | 提示指定英文短语。实际动作和因果关系需要人工核对。 |
| `5` | 模糊归因 | 提示指定中英文表达。人工核对附近是否已有具名来源。 |
| `7` | AI 常用词 | 提示指定英文词。抽象含义、术语和必要限定需要人工判断。 |
| `8` | 迂回表达“是”或“有” | 提示 `serves as`、`stands as` 和 `boasts`，不把 `features` 当作禁词。 |
| `9` | 模板化否定对比 | 提示 `not just ... but` 和 `not only ... but`。真实对比可以保留。 |
| `10` | 强行三段式 | 人工判断分组是否来自内容，三项列表本身不触发提示。 |
| `11` | 同义词轮换 | 人工核对同一对象的名称。 |
| `12` | 虚假范围 | 人工判断 `from ... to` 是否表示真实范围或顺序。 |
| `13` | 破折号 | 提示正文中的长破折号，受保护的引用仍由人工判断。 |
| `14` | 冒号过多 | 人工区分连接句、定义、列表和示例。 |
| `15` | 加粗过多 | 人工判断重点与 UI 标签，不设固定数量门槛。 |
| `16` | 加粗列表标签加冒号 | 提示该结构。标签是否重复正文需要人工判断。 |
| `17` | 英文标题大小写 | 人工使用 sentence case，同时保留名称和缩写。 |
| `18` | 装饰性 emoji | 提示标题与列表中的指定符号范围，人工区分装饰和实际内容。 |
| `19` | 弯引号 | 仅在没有中文的行中提示。中文引号保持正常用法。 |
| `20`、`22` | 聊天残留和恭维 | 提示指定中英文套话。 |
| `23` | 填充语 | 提示指定英文短语，建议短词或删除。 |
| `24` | 重复缓和词 | 提示相邻组合，人工保留不同层次的不确定性。 |
| `25` | 泛泛结尾 | 提示指定中英文套话。 |
| `26` | 抽象比喻名词 | 提示指定短语，不把 `vector`、`surface`、`primitive` 和 `harness` 裸词判为问题。 |
| `27` | 感受式描述 | 人工检查句子是否给出操作、机制、事实或数字。 |
| `28` | 难读长句 | 人工检查指代和从句，不以长度判定错误。 |
| `29` | 被动语态 | 人工判断执行者是否重要，不机械匹配过去分词。 |
| `30` | 副词代替测量 | 提示指定改善声称，人工核对测量依据。 |
| `31` | 复杂词代替常用词 | 提示指定英文词，人工保护专业用法。 |
| `32` | 修辞和口号 | 提示指定固定表达，其他修辞由人工复核。 |
| `33` | 过度压缩 | 人工检查省略的主语、动词、冠词、缩写和符号。 |

通用检测与参考摘录排序使用不同规则。后者只在 `memory.py` 中评价研究摘录，不能作为用户草稿的阻断规则。
